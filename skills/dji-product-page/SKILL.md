# DJI 参考风格产品页

把原型落成与 PixelMob 2026-09-22 页面相同设计语言的可运行前端。直接使用这里的视觉基线，无需重新发散三种风格。质量目标是图文卖点清晰、匹配、易读，让真实产品和使用画面承担解释。

这里的“DJI 风格”指本次经用户调整后的设计结果，不是 DJI 官方设计规范，也不复制 DJI 品牌、文案和图片。业务事实、栏目数量与转化目标由新项目决定。

## 读取输入与版本

开始说明使用本技能。先读当前项目约定、已确认原型、最新文案/反馈、图片/视频/字体、现有代码与启动方式。原型若来自飞书，检查当前版本；不能把旧导出当作最新画布。

优先级：用户最新明确决定 → 本项目已认可的当前页面/原型 → 原始 brief → 外部参考。冲突影响事实或主要转化时澄清对应项；一般排版与素材选择自行完成。

有 `$feishu-website-wireframes` 的 manifest 就接续其 section ID。没有也可从现有原型提取一份轻量记录：模块目的、实际文案、证据素材、版式、CTA、状态、缺项。不要为格式完整强制用户重做原型。

## 固定视觉语言

实现前阅读 [visual-system.md](references/visual-system.md) 与 [media-and-motion.md](references/media-and-motion.md)。它们已提炼本次风格，新项目无需重新访问 PixelMob。需要解释判断来源时再读 [pixelmob-lessons.md](references/pixelmob-lessons.md)。

- Inter，无衬线、紧凑大标题、清晰字重；大多数章节标题左对齐版心，Hero 可居中，按内容保留明确的例外。
- 统一约 1200px 版心；全出血 KV 与环境大图有意突破版心，其余标题、Tab、媒体和表格共用边界。
- 白/浅灰与近黑整段切换，大画面与充足留白构成节奏；避免连续多段同构小卡。
- 亮点采用图片/短视频为主体的宽窄卡片；功能 Tab 用浅灰胶囊容器、白色选中项。
- 彩色只用于有意义的转化、数据或平台入口。众筹 CTA 可用 KS 绿；不是众筹就使用本项目主行动色。
- 整块内容 0.7 秒、24px 上移淡入；不默认加入字词错峰、首屏背景缩放、强制滚动或夸张视差。

可复制 [assets/design-tokens.css](assets/design-tokens.css) 作为新项目起点。它只有命名变量，不包含客户素材或业务结构；已有项目将值映射进原有系统，避免叠加第二套全局样式。

## 从原型到实现

先检查原型的阅读任务、主次和内容容量。批准过的原型仍可能在真实图文与手机宽度下过载；这类问题要在静态结构阶段解决，不能靠套风格和加动效掩盖。按 [阅读层级与内容过载](references/visual-system.md#阅读层级与内容过载) 检查，在授权范围内选择拆分、分组、Tab、轮播或重排；保留明确固定项，业务信息搬移记录去向。确需改变用户固定结构时给出具体建议，继续不受影响的部分。

1. **先选能证明内容的素材。** 查看真实文件和视频镜头，记录用途、时间码、清晰度、桌面/手机裁切。不要先画满装饰再找图填洞。
2. **先落关键视觉组件，再复用。** Hero、亮点网格、一个功能 Tab 足以校准字号、版心、圆角和图文关系。检查成立后继续全页；不强制停下来等待额外审批。
3. **按阅读目的实现后续章节。** 流程保留路径，信任呈现证据，选型字段对齐，FAQ 解决最后疑虑，收尾用清楚的场景和同一主要转化。
4. **允许有依据的内容调整。** 删除重复眉题、序号、口号和冗余说明，必要时由叠字改上图下文；保留确认事实、重要条件和目标。不能擅自把精简变成删关键功能。
5. **同步结构变化。** 模块增删、顺序、语义或证据改变时更新交接记录；原型写入也已授权才回写飞书，否则明确列出待同步项。不要声称两端自动同步。
6. **最后补动效并校验全页。** 静态构图先成立，动画只增强阅读；包含未选中的 Tab、媒体失败与手机短屏状态。

沿用项目技术栈；没有现成工程、用户也没指定框架时，采用原生 HTML/CSS/JavaScript 与简单本地启动。为取得这类视觉效果无需引入整套 UI 框架。素材、源码和构建输出分开保存，源文件可追溯；不要编辑构建产物或把历史 CSS 覆盖层全搬进新项目。

## 文案与事实边界

标题表达利益，正文只补必要解释；亮点标题通常不超过两行，说明约两行，实际容器宽度优先。每个 Tab 图文都解释各自功能。

性能数字、型号差异、赠品、历史众筹、量产/交付状态必须有项目来源。不同来源冲突就保留不确定性或向用户询问，不能从高配推导低配。区分工程样机画面与当前产品承诺。

主 CTA 文案保持一致，但目的地可以按用户选择区分型号 reward 或相关章节；统一文案不等于抹掉目标锚点和归因参数。桥接页不默认添加购买、订阅或邮件收集等竞争漏斗。

## 完成标准

运行项目现有检查/构建并启动本地预览。浏览器检查至少一个桌面宽度和 390px 左右手机宽度，复杂网格再加平板；另关注短屏首屏是否遮挡 CTA。修复阻断错误。

- 标题、Tab、媒体、表格版心一致；手机无整页横向溢出、裁切不丢关键主体，文字不挡操作 UI。
- 每段主信息、证据、补充有清楚层级；桌面和手机实际阅读都能辨认话题边界，不能仅凭“没有溢出”通过检查。修复已识别的混杂、等权堆叠和过度压缩，或说明用户明确保留的限制。
- 所有 Tab/轮播项内容可用、入口和当前位置清楚，切换不明显跳高或截断内容；键盘、焦点、ARIA、FAQ、导航与返回行为匹配。轮播有明确前后操作；自动播放可暂停，不强行打断阅读。
- 视频实际可播或有清晰静态兜底；暂停按钮有效，隐藏/离屏视频不抢资源，自动播放失败不留下黑洞。
- reduced-motion、无 JS/脚本失败时核心内容仍可读；滚过的内容不重复入场。
- 所有图片/字体/链接能加载，真实 CTA 目标与已有查询参数/锚点保留；未配置目的地如实标注。

交付可查看的预览/入口、源码位置、已执行验证和实质待定项。创建页面不自动扩展成发布、购买服务或改写外部参考；已明确授权的发布按对应工作流继续。

## Shopify 转换

单纯制作静态页不等于已适配 Shopify。用户实际要求转换时遵守当前 AGENTS.md：先检查源文件和运行假设，拆成有效 theme/Liquid 结构，使用可用的 Shopify 开发 MCP 验证 Liquid、schema 与资产引用，再执行 Theme Check/构建和本地 Shopify 预览启动，修复阻断错误。

没有适用的 Shopify MCP 时明确说明，按项目约定暂停转换并询问是否接受有记录的替代验证；普通商店查询工具不等于主题验证。最终报告具体 MCP 验证、执行命令和 Shopify 是否成功启动，不能用静态预览代替。
