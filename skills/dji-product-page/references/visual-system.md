## 阅读层级与内容过载

这类大画面风格依赖内容主次；留白、字号、圆角不能修复所有信息等权的问题。每段有清楚的阅读目的，可用分组、Tab 或轮播承接多个信息块；每个可见状态都用主标题与画面表达结论、用证据支撑、用可读的次层级承接补充。

实际放入图文后，逐段检查：

- **分组是否清楚**：功能、历史成绩、选型、疑问若放在同段，要有明确分组或切换入口；不能仅因 brief 写在一起就等权堆放。亮点总览、流程和型号比较都可以含多项。
- **视线是否有顺序**：多个大标题、数字、图片或按钮同时抢主位时，按业务重点调整位置、尺寸与分组；正文保持可读，不能只把次要内容变淡变小。
- **桌面是否靠压缩成立**：真实文案挤占画面、挡住操作，或需要缩字、裁切、截断才放得下时，先去重复、拆组、换图文关系，再改高度。页面可以变长，但不能只是把混杂内容原样拉长。
- **手机是否仍有分组**：多列变单列后重新检查顺序、组标题、段落间距和条件归属；不要把桌面所有卡片机械串成长列表。

处理顺序为：确认主信息 → 合并重复 → 选择分段、分组、Tab 或轮播 → 安排内容去向 → 调整布局 → 桌面与手机复查。关键主张可在 Tab/轮播中展示，入口要能说明内容，型号差异和必要条件跟随对应项；记录搬移后的 section ID 与状态。

Tab 适合按功能、场景或类别选择内容；轮播适合浏览多条卖点、媒体、案例或步骤，两者都是正常设计方案。轮播让人看得出还有内容、有当前位置和前后按钮，手机可增加滑动操作；每项可手动访问，自动播放时允许暂停。连续步骤保留顺序和回看能力；必须同时比较的内容避免让访客靠记忆反复切换，可保留对照表。沿用现有版心、字体和克制动效，无需为轮播另加一套视觉风格。

切换后的每一项都检查真实图文容量、可读性和手机状态，不能只让默认态成立。核心卖点不必全部同时展开，但要可发现、可访问，不能裁切、遗漏或脱离关键条件。

不硬性限制每段字数、卡片数或屏数，也不把每项能力拆成独立大章节。用户明确固定的文案和结构优先：在约束内改善层级，无法兼顾时说明具体取舍，不默默覆盖决定。

## 模块配方

### 1. 一屏视频 Hero

100vh 作为本次桌面基线；移动端用合适的 viewport 单位/高度策略保住标题与 CTA。上部是短标题和一句支持文案，下部是短说明与行动。主体画面占大多数面积。

视频铺满但保留真实设备，方向性遮罩只压文字安全区；封面与首帧保持构图连续。避免把整个画面压成看不清产品的黑底。导航、短屏首屏、底部固定 CTA 不互相遮挡。

### 2. 视觉亮点网格

最终页面是九卡，在桌面四列中排列：

```text
|   主性能（2列）    | 容量 | 保护 |
|   功能 A（2列）   |   功能 B（2列） |
| 功能 C | 屏幕 | 连接 | 供电 |
```

起点为 336px 行高、16px gap、10px 圆角、约 28–30px 内边距。宽卡用于最重要数字或需要横向空间的动作，窄卡处理单一事实。卡片底图是真实产品/界面/动作，文字叠放在已设计的安全区。

这个九卡排列用于重现本次密度，不是所有产品必须凑九项。按实际内容选择数量，保持少量可复用版式。不要让窄保护卡无故跨两行而留下弱画面与大空洞。

约 1100px 以下可改两列，约 700px 以下单列；重设每张图的焦点，手机卡片通常接近正方形。卡片文字不能依赖截断省略才能成立。

### 3. 大画面与流程

环境整图可以建立专业摄影语境；流程作为独立部分清楚呈现 Before/Now。用细线、亮灰步骤、克制标题表达关系，不依赖霓虹、发光芯片或悬浮装饰。

素材拥挤时，把说明移到图片外，不继续叠遮罩和更多卡片。大型实际操作视频与少量关键参数是证明核心价值的主要空间。

### 4. 胶囊 Tab

外壳 `#E9E9EB`、圆角 999px、padding/gap 4px，默认左对齐版心。按钮约 44px 高、16px/500、padding 12px 28px；选中项白底黑字、极轻阴影，非选中项灰字。所有功能/场景 Tab 共用该组件。

手机外壳适应宽度，按钮等分、约 14px 字号，长标签允许合理换行；不要挤出屏幕。大媒体桌面常用 16:9；手机按内容选择 4:3 或近方形，不能裁掉关键 UI。

所有状态使用同一内容骨架，面板高度稳定。支持方向键/Home/End 与正确焦点；隐藏面板不能仍可点或出现在辅助阅读顺序中。

### 5. 信任证据

深色大章节，左右两组真实照片与事实，下方短标题和少量大数字。图说写清对象与阶段，数字写清归属。金额可用橙色，其余保持灰白。不要把完整段落塞进多个漂浮小卡。

### 6. 选型、FAQ、收尾

型号名称和产品图优先；对应规格同顺序对齐。产品图保持原比例，保证比较中的视觉尺度合理。字段根据资料完整度决定，不用一堆“待定”凑满表。

FAQ 用可读的列表、细分隔线和少量展开内容，不另造复杂卡片风格。收尾以清晰场景大图、短利益和主 CTA 完成叙事。手机保住主体；背景素材模糊就换更清楚的来源，不能靠遮罩掩盖。

Footer 延续整页尺度，链接和服务信息来自当前业务。订阅区不是默认模块。

## 这类风格应避免的结果

- 无意义全大写眉题、每段固定序号、同义口号堆叠。
- 一切都居中，或标题/Tab/图片各用不同左边界。
- 所有模块都变成三张均匀小卡；卡片里再套素材卡和文字卡。
- 渐变标题、紫色 AI 光、装饰芯片、彩色流程线承担本该由证据承担的工作。
- 截帧模糊、图文不匹配、远景产品充当所有功能演示。

少量真实步骤编号、深浅标题层级和有意义的标签仍可保留；避免将局部删减反馈变成绝对禁令。
