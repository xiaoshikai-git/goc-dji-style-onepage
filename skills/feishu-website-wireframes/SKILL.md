# 飞书网站原型与文案

产出能直接进入 UI 和前端的黑白灰原型：每段明确用户问题、实际文案、视觉证据、布局容量和动作。可编辑对象与最终阅读效果同样重要。

本技能处理原型与内容。用户只要原型时，交付到画布和交接文件。默认中文沟通，页面语言跟随 brief 或当前版本。

## 输入准备与人机分工

接收新项目或用户询问如何准备资料时，阅读 [用户准备与协作规则](references/user-input-guide.md)。需要收集信息时，可提供 [需求填写模板](assets/project-intake-template.md)；先从已有材料提取，缺什么再补，不要求用户重复填表。

开工需能识别产品/业务及可信事实依据、主要受众和页面目标、本次范围与语言、既有版本和不可变约束。用户可以明确交由 AI 提议某项；此时记录假设并先做方案，不能把未确认的产品事实写成承诺。资料格式和整理程度不作为额外门槛。

飞书实际写入前需有明确目标画布、可用编辑权限，以及新建/替换/局部修改范围；这些缺失只阻塞写入。素材、视觉参考、视频时间码和完整成稿不是通用开工条件；AI 应负责整理来源、看素材、规划结构与写文案。缺证据的模块给出具体素材需求，标明可交原型的程度。

读取后简短反馈“理解的目标与范围 / 采用的资料版本 / 关键缺项与处理方式”，在已有授权范围内继续，不把此摘要变成例行审批。只有会实质改变结果且无法合理推断的缺项才集中询问。

## 范围与版本

- **单页**：画一张从 Header 到 Footer 的完整长页。必要 Tab 状态紧邻所属模块，不默认展开整站、组件库、投放变体和大量旁注板。
- **整站**：实际页面横向组织，各页向下展开；共享组件在有复用价值时独立展示。
- **局部修改**：先读当前飞书画布与最近用户修改，只替换相应模块；旧本地导出不能覆盖较新的线上内容。
- **前端反推原型**：对照用户认可的最新页面、当前原型与反馈，提取结构/文案/素材变化。区分已采用、提议、待同步；最终页面不等于已同步画布。
- **只要本地文件**：生成可编辑源文件与预览，不自动写入飞书。

开始说明使用本技能。读取 brief、当前画布、现有代码/截图、产品资料、真实素材与参考页面。只询问材料无法回答且会改变结果的缺项，例如主要转化、语言、目标画布；缺目标时继续本地工作。

## 先定叙事与证据

绘制前阅读 [content-to-layout.md](references/content-to-layout.md) 和 [design-system.md](references/design-system.md)。需要选择页面角色时再读 [page-patterns.md](references/page-patterns.md)。

1. 明确页面任务及主要转化。Bridge Page 的认知与外跳、PDP 的购买、品牌首页的分流不能混用；转化目标由本项目决定。
2. 把原始卖点翻译成用户收益，给每段一个主要问题和答案。区分事实、证据、提议文案和限制条件。
3. 先审素材能证明什么、缺什么。参考页应拆解画面面积、阅读顺序、图文比例和状态组织，不能只取装饰样式。
4. 分配内容深度：亮点负责扫读，详解负责证明，FAQ 解决疑虑，选型支持比较。同一卖点再出现应增加解释或证据。
5. 按最终比例放实际短文案，检查大小卡片、宽窄栏、Tab 各状态容量。标题与正文不要为填格子而加长。

保留用户明确确认的事实、措辞和目的地。可优化重复说明与布局，但不能为简洁丢掉核心关系、删除关键卖点或改变承诺；必要条件通过简短正文、注释或对应 FAQ 保留。

## 内容过载先整理，再画原型

业务资料的分组不自动等于页面分段。用户没有明确固定布局时，AI 负责选择分段、分组、Tab 或轮播，合并重复项并排清主次，不要求业务同事先会排版。按 [内容分段与层级规则](references/content-to-layout.md#内容分段与层级规则) 执行：

- 每段有一个清楚的阅读目的，能用一句话说清“访客来这里能了解什么”。可用分组、Tab 或轮播承接多个信息块；每个可见状态都要分清主信息、证据和补充，避免同时抢主位。
- 无关问题混放、入口含糊、实际文案挤压画面或手机阅读失去分组时，主动选择拆段、段内分组、Tab 或轮播。不能靠缩字、压行距、截断或层层套卡解决；切换后的每一项也要清楚易读。
- 完整保留需要呈现的业务信息，但不必等权或同时展示。Tab/轮播中的内容要有清楚入口，关键型号差异、限制和行动条件跟随对应内容；搬移、合并的内容在交接记录中有去向。
- 亮点总览、流程、对比可以含多项，只要服务同一个阅读任务。不硬性规定“一段三项”“每段一屏”或把每个卖点都拆成一段。

已有授权范围内直接整理，并简短说明依据。明确要求固定文案、顺序或同段展示时，先保留约束做层级优化；确有无法兼顾的冲突，再给具体方案让用户取舍，不把每次拆段变成审批。

## 一份交接依据

使用已有内容清单，或建立 `page-manifest.json` / 等价 Markdown。字段与示例见 [handoff.md](references/handoff.md)。清单与画布使用相同 section ID，记录：

- 页面目标、语言、主要 CTA、当前版本及模块顺序。
- 每段的问题、主要结论、主次层级、实际标题/正文/CTA、事实来源与适用型号/条件；发生拆分或搬移时记录内容去向。
- 布局类型、媒体角色/比例、文字安全区和移动端重排原则。
- 状态内容、默认态、触发/结果/返回、待定素材与缺失资料。

只记录影响评审和实现的内容。事实来源与制作说明放页面外或交接文件；页面本体只呈现访客应看到的内容。内部编号不默认变成上线文案。

整站清单区分独立页面、共享模板、组件状态和外部系统，标明已绘制/模板覆盖/外部承接/待定。不把每个按钮扩成新页面，也不因模板库里没有就漏掉明确需求。

## 原型阶段的落地检查

导入前在正常阅读比例检查：

- **扫读**：只看标题和画面，能否理解产品类别、主要价值和下一步？
- **分组与主次**：每段目的、入口和切换关系是否清楚？当前状态能否分清先看什么、证据在哪、哪些是补充？对已识别的过载先修正，再导入；用户明确选择保留的结构注明限制。
- **图文互证**：画面能否证明该功能？相邻模块是否拿同一种画面解释不同能力？
- **容量**：标题、正文、数字、单位及条件能否放入实际框宽？先改写/换版式，再调高度，不靠缩小正文解决。
- **节奏**：大画面、亮点、流程、Tab、证据与对比按内容需要变化，不把每段都套成三张小卡。
- **核心关系**：流程对比有路径，信任有证据，型号比较按相同字段对齐。
- **状态**：Tab、轮播在所属模块旁画必要状态，标清入口、切换方式、当前位置和内容归属；不能只完成第一项。重复普通状态可留在清单，不自动扩成满板。
- **手机原则**：即使只交桌面原型，也记录关键裁切、列变行、Tab 和按钮处理；用户需要时再绘制完整手机画布。

发现真实文案或素材放不下，就在这一阶段修正并更新清单。A/B 对比在用户要求或确需保留方案时生成，标清差异；不要自行混成第三套未经说明的版本。

## 生成与飞书写入

阅读 [feishu-workflow.md](references/feishu-workflow.md)。优先用当前明确支持画布节点的工具；没有适用连接器时，通过浏览器正式界面导入 `.drawio`。

`scripts/canvas.py` 提供原生文本、矩形、线条、媒体框和按钮，输出未压缩 draw.io XML、几何清单与 PNG。用法见 [builder.md](references/builder.md)。它只处理几何与文件，不决定内容、验证事实或证明线上导入成功。

先完成可审阅本地文件，再执行已授权写入。“在这个画布输出/修改原型”已授权指定范围；仅提供参考链接不代表授权改写参考。前端任务发现原型差异时先写同步清单，修改画布也在授权范围内才回写。

文字、按钮、卡片与区块应能在飞书独立编辑。真实照片可为图片对象；整页 PNG、SVG 或 PDF 不能替代可编辑原型。

## 验证与交付

本地检查 XML、边界、文字容量、覆盖及 CTA 去向。飞书中检查总览、正常比例的复杂模块、文字/形状独立可编辑、修改接缝与保存状态；必要时重新加载验证。

局部更新保留当前 Header/Footer 和用户内容；高度改变时同步移动后续模块。导入结果不明时先观察，不重复导入叠加。

交付画布链接、可编辑源文件、范围与影响落地的待定项。未写入则明确“本地已生成，尚未写入飞书”。状态图仅代表意图，不能声称播放、提交或跳转已实现。

## 来源与边界

[source-analysis.md](references/source-analysis.md) 记录原型方法与 PixelMob 风格的提炼依据，解释来源时再读。新项目不必访问客户项目，也不复用其事实、素材、价格与联系方式。

原型可交给 `$dji-product-page` 实现本次 PixelMob 的 DJI 参考风格；该技能不可用时，交接文件仍可独立使用。其他风格不受此限制。

后续真正转换为 Shopify 主题时，遵守当前项目 AGENTS.md 和 Shopify 工作流；只画购买路径不触发主题构建或 Shopify 启动。
