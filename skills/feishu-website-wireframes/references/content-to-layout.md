# 从内容、证据到能落地的原型

## 用用户问题选择版式

先写内部目的，例如“让访客相信这不是第一次做硬件的团队”；选证据，例如“上一代产品及对应众筹成绩 + 当前产品工程样机实拍”；最后决定两栏、整图、流程或卡片。

brief 中的“Brand / Team Trust”是内部任务；“A proven team. A working prototype.”是用户读到的答案。标题按本项目改写，不能套用不真实的承诺。

## 内容分段与层级规则

### 先分阅读任务，再决定 section

把 brief 当作资料来源。业务同事写在同一段、同一张表或同一个标题下的东西，可以在页面中重新组织；“这些都要保留”不等于“这些必须挤在同一段”。用户明确固定的布局除外。

先为候选章节写一句“看完这一段，访客会明白……”，再安排：

| 层级 | 放什么 | 怎么呈现 |
| --- | --- | --- |
| 主信息 | 这一段最需要记住的结论 | 主标题与主要画面；同一局部不要制造多个同等强度的焦点 |
| 支撑证据 | 证明结论的动作、图像、数据或对比 | 紧挨对应主张，按关系排列，不给每条证据再套一层完整章节 |
| 补充信息 | 需要时再细看的说明、规格或疑问 | 就近说明，或进入有明确入口的参数/FAQ；影响主张的条件不能远离正文 |

“快速了解核心能力”“比较两种型号”“看懂一套流程”都可以是一个阅读任务，因此允许一组卡片、多行参数或多个步骤。内容也可以通过 Tab、轮播分组展示；每个状态内部排清主次。不要把“一段一个任务”理解成“一段只能一句话、一张图或一个卖点”。

### 这些信号需要重新分组

- 一个标题下混放功能收益、团队经历、型号选购等不同问题，却没有清楚的分组、入口或切换关系；只有泛标题、看不出各块内容归属。
- 多个大标题、大数字、主图和按钮等权出现，看不出先看哪里；同组卡片中有的只是一句事实，有的却承载完整故事。
- 正常字号与比例下，长文挤压证据画面、叠字挡住关键动作，或需要缩字、截断才能塞进原定几何框。
- 手机列变行后，不同话题连成长串，缺少可识别的组标题、停顿或阅读顺序。长本身不是错误，无法判断段落归属才需要调整。

上述信号触发判断，不机械按字数、卡片数量或屏数判不合格。

### 调整顺序

1. **排主次**：依据已定受众、页面目标与业务重点确定主信息。业务优先级不明时提出有依据的建议；只有会改变定位或转化的冲突才需用户决定。
2. **去重复**：合并同义说明和重复装饰标题；保留所有独立事实、必要条件和明确要求保留的文案。
3. **按问题分组**：选择拆段、段内分组、Tab 或轮播，依据阅读方式决定，不默认拆成长页。每组内部用“收益 → 证据 → 细节”的顺序组织，而不是先画固定数量的格子。
4. **决定内容去向**：主张与关键限制就近呈现，详细规格可进入比较/参数，常见疑虑可进入 FAQ。核心卖点也可以放在 Tab 或轮播中，但入口应能说明里面有什么；价格条件、型号差异跟随对应内容展示，不能被截掉或移到难以关联的角落。
5. **再选版式**：复杂操作用大画面，路径用流程，比较用对齐字段；主信息用更明确的位置与尺度，补充信息保持可读。不要默认所有内容变小卡。
6. **检查手机**：按实际顺序阅读标题、证据、条件和动作；必要时重排与分组，不只把桌面多列改成一列。

### Tab 与轮播都是正常方案

| 阅读方式 | 可采用的组织 | 必须交代清楚 |
| --- | --- | --- |
| 按兴趣选择功能、场景或信息类别 | Tab | 标签说明内容，每项有对应图文，当前选中项明显 |
| 浏览多个卖点、案例、媒体或一组步骤 | 轮播/分步切换 | 看得出还有内容、当前位置和总量；有明确前后切换方式，手机滑动可作补充 |
| 同时比较型号、价格或前后差异 | 对照布局/表格，也可与 Tab 配合 | 访客无需靠记忆来回切换才能完成关键比较 |
| 连续理解不同主题或证据链 | 分段，或带清楚顺序的分步轮播 | 标题和位置提示帮助理解顺序，前后内容可回看 |

重要内容不必全部同时展开。检查的是能否发现、能否方便切换、每一项是否清楚，以及条件是否跟随对应主张。轮播默认可手动操作；若采用自动播放，应允许暂停，不让阅读被强行打断。不要为了减少页面长度把所有内容变成没有清楚标签的滑动项。

不靠固定高度裁切、缩小字号、压紧行距、嵌套卡片或无限加长掩盖结构问题。Tab 与轮播切换后的内容也要通过容量检查，不能只让默认态好看；不以“看起来干净”为由删掉业务要求。

### 一个拆分例子

输入把“备份速度、操作步骤、九个功能、团队经历、两款型号和 FAQ”都放在“产品优势”下。

可按阅读顺序分成：核心收益与速度证据 → 操作流程 → 其他能力 → 团队与产品成熟度 → 型号比较 → FAQ。其中功能可以做 Tab，多个卖点或流程步骤可以做轮播；也可以在一个大章节内用明确入口分组。具体方案依页面目标调整，核心速度避免重复长篇解释。每个状态内部仍排主次，不只是拆成更多框或把内容机械装进切换面板。

整理后在已有交接文件简记“原分组的问题 → 新分组与主信息 → 原内容去向”。继续在授权范围内绘制，无需另加表单或默认审批轮次。

## 内容容量

以下是英文硬件落地页的起点，以实际框宽、字号及已定文案为准；中文以实测行数判断。

| 位置 | 起始容量 | 重点 |
| --- | --- | --- |
| Hero 主标题 | 1–2 行，约 5–12 词 | 类别/利益优先，不写功能清单 |
| Hero 支持文案 | 1 句，约 15–28 词 | 补场景与用途，不重复标题 |
| 主章节标题 | 1–2 行，约 4–10 词 | 读完知道本段说什么 |
| 章节引导 | 1–2 句，约 18–36 词 | 与画面分工 |
| 亮点标题 | 通常 2 行，约 3–7 词 | 同组语法相近，数字/单位可独立 |
| 亮点说明 | 约 8–16 词，通常 2 行 | 一项收益，可不写，不能凑字数 |
| 场景 Tab | 短标题 + 一句 + 少量能力标签 | 说处境和结果，不重复全部功能 |
| 条件/来源 | 能读清的短注释 | 不隐藏会改变理解的条件 |

检查单位、型号、介词是否孤行；同组大小写与语法统一。标题默认自然句式，型号/缩写保留准确大小写，不随机混用全大写眉题、序号和口号。

删减顺序：内部标签 → 重复眉题/口号 → 重复解释 → 无必要 CTA。不能删掉适用型号、数字条件、备份限制等重要内容。

## 模块如何落地

### Hero

标出产品主体、标题安全区、主 CTA、手机裁切区。灰阶也应表达真实画面面积；不要把视觉 KV 画成文本块旁一个小 IMG 框。视频注明封面和播放意图，原型不必实现播放器。

### 亮点卡片

按强弱、画面方向与文字长度决定跨度，统一少数版式，例如“大数字 + 实物细节”“功能标题 + 屏幕动作”“利益短句 + 场景”。先在最大和最小卡片放真实内容，放不下就改写、合并重复项或换跨度。

窄卡不因字多就拉成两倍高；横向 UI 和连续动作更适合宽卡。跨行卡必须同时适合内容与构图。六张、九张、三列、四列都是项目选择；不能为了数字整齐漏掉卖点和条件。

### 流程对比

看得出起点、顺序、交接点、终点。“很多设备 → 一台”只说明数量变化；若价值是减少交接，Before/Now 都要有可读路径。保持对照轴一致，可用多设备串联与同设备内连续动作对照。

流程图已解释清楚时，相邻场景大图只承担情境，不叠第二套流程文字。

### 功能演示与 Tab

一句利益、一块大演示、少量事实往往比多层卡片清楚。Tab 共用外框、媒体比例与标题层级，明确默认态，每项都有不同证据。

Review / Cull / Create 应看出查看细节、选择照片、改变效果的区别；不能三项都用同一张设备远景仅换标题。

### 信任

按疑虑组织证据，不堆品牌形容词。经验与成熟度可为两组：以前交付过什么；现在真实做到了什么。历史数据写清归属，报道不自动等于背书，工程样机不等于量产交付。没有事实就留缺口，不造评价、金额和认证。

### 选型

先呈现型号、产品图和适合谁，再按相同顺序列影响选择的规格。对齐字段、统一单位，来源与型号对应。未知项缺省或询问，不能从 Pro 推导 Standard。

桥接页是否要详细参数由用户最新要求与决策需要决定；“不能有参数表”不是永久规则。交易仍由目标平台承接。

## 素材框交代四件事

1. **证明什么**：插卡备份、完成校验或选择照片，而非“科技感”。
2. **画什么/有什么**：主体、动作、必须看清的 UI；已有素材写文件/时间码。
3. **如何排**：比例、主体位置、文字安全区；拥挤时用上图下文。
4. **手机如何保留**：裁切焦点、换竖图或改上下排，不等比缩小。

复杂拍摄说明留页外，框内一句镜头说明。先检查素材真实尺寸、清晰度和镜头，不只看文件名。

## 从反馈回修

将“不自然、太弱、太多、AI 味重”转成可处理的问题：关系没看懂、证据不匹配、文字挡主体、卡片过密、装饰过多或尺度不统一。改对应的内容和布局。

记录 `section ID / 原问题 / 采用修改 / 保留事实与目的地 / 画布同步状态`。删除一次编号不等于任何数字都禁用；某章节改左对齐不等于 Hero 也要左对齐。
