# 画布结构与视觉语法

以下是从示例归纳的起点，可以随用户参考、页面密度和品牌要求调整。

## 整站画布

- 左上写 `品牌 WEBSITE WIREFRAMES/PROTOTYPE` 和日期/版本。
- 单页直接包含 Navigation + Footer；整站有复用价值时再独立展示共享组件，按主旅程横向排主要页面。每页顶部对齐；长页面向下延伸。
- 列表对应的详情、轮播第二屏、视频弹窗等放在关联页面下方或旁边，标注所属页与状态。
- 一条横排过长时，按购买、品牌内容、支持、业务合作等分区换行；保持阅读顺序，不机械限定列数。
- 页面标签放在页面外，黑底白字，清楚区分页面、模板和状态；用户侧标题放在页面里面。
- 模块 ID/编号放页外或交接清单；真正帮助访客理解的操作步骤才在页面内编号。外部注释以 `PAGE-ID / SECTION-ID` 指回对象。连接线只解释关键流程和状态。

## 桌面默认尺度

| 项目 | 起始值（画布单位） |
| --- | --- |
| 页面宽度 | 1200 |
| 左右内容边距 | 64，内宽 1072 |
| 页间间隔 | 240–360 |
| 栅格间距 | 24–32 |
| 共享 Header | 约 104 |
| Hero / 技术叙事大段 | 通常 600–760，按实际内容调整 |
| 主标题 | 40–48 |
| 模块标题 | 28–32 |
| 卡片标题 | 21–25 |
| 正文 | 18–20 |
| 导航与按钮 | 16–18 |
| 注释 | 14–16 |
| 按钮高度 | 44–48 |

正文避免为了塞进固定框而持续缩小字号。先删重复信息，再增加内容高度；下方模块及页脚一起移动。长页面不等于整页缩成一屏。

上表适合一般信息型原型。若目标是 PixelMob 本次的视觉型产品页，使用接近成品的尺度：桌面 H1 约 56–76、主 H2 约 48–64、正文 16–18、章节上下留白约 96–120。按版心和实际文字测试，不能用小字号线框假装大字号 UI 能装下同样内容。Hero 表达一屏高度，大媒体常用 16:9；亮点按优先级设宽窄跨度。

默认做桌面主版，并记录关键模块的手机重排/裁切原则。用户要求移动端时补关键页面与状态的移动版；建议宽 390、边距 20，按内容重排为单列，不能等比缩小桌面。未绘制的端在交付中说明。

## 灰度系统

- 背景 `#FFFFFF`；相邻段可用 `#FAFAFA` 区分。
- 媒体框 `#EEEEEE`，辅助区域 `#F4F4F4`。
- 主文字 `#222222`，次文字 `#666666`，边线 `#BBBBBB` 或 `#DDDDDD`。
- 主 CTA `#171717` 底白字；次 CTA 白底深边。
- 大标题、Hero 或视频 KV 可以反白。低保真也要表达主次关系。
- 默认简洁无衬线与方角，无需加入装饰渐变或精细品牌视觉。用户已提供并要求保留的图片、信息图和组件可以复用。

## 模块最小内容

| 字段 | 应表达什么 |
| --- | --- |
| 目的 | 本段回答用户的哪一个问题；留在策划注释 |
| 标题 | 对用户有意义的一句话；避免只有内部模块名 |
| 文案 | 能判断信息层级与长度的实际草稿 |
| 媒体 | 拍什么、展示什么、比例或镜头用途 |
| 动作 | 明确 CTA，去向是页面、锚点、状态还是外部系统 |
| 状态 | 选中、展开、错误、下一屏等关键差异 |

媒体卡不一定都需要正文。简单场景通常“图 + 场景名 + 一句话”；视频卡可以“画面 + 播放符号 + 标题”。不要把原本简明的卡片变成内容简报。

## 共享组件

先确定导航和页脚，再复用到整站。单页不默认增加独立组件区；整站组件区可展示导航默认态、菜单展开态、页脚与必要系统控件。

共享导航项目来自当前站点结构。页脚按业务分组，例如产品、支持、品牌、政策；语言/地区、社交及付款方式按市场和实际能力展示。不要把参考案例的四列或支付图标当作所有项目的固定内容。

PDP 的页内导航属于 PDP 内容的一部分，不用它替换全站 Header。系统结账、账户或客服页应标注由相应平台承接以及原型可表达的范围。

## 内容真实性

保留客户给定的卖点与模块，区分已确认事实、客户示例、拟议文案和缺失资料。品牌故事可以写作“提议文案”；不能虚构创始人履历、消费者引言、评级、认证、销量或响应时效。

业务未提供真实素材时，给出足够具体的素材需求。高风险或依赖产品说明书的使用步骤引用待提供的正式说明，不编造故障码、安全限制或维护方法。

正式文案内保持清爽；待定信息主要集中在页外交接区。需要用数值占位来判断布局时，明确其为示例，不能在其他页面变成已确认承诺。
