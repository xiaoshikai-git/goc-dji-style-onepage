# 页面角色与可选编排

这是模块选择库，不是强制 sitemap。先匹配需求，再决定页面与模块数量；保持用户明确要求的顺序与内容。

## 先区分页面角色

| 类型 | 用户问题 | 典型下一步 |
| --- | --- | --- |
| Home | 这是什么品牌、能给我什么、从哪开始？ | 产品介绍、购买、解决方案 |
| Product Overview | 适不适合我、怎么工作、为什么值得考虑？ | 购买配置或深入了解 |
| PDP | 买哪款、多少钱、包含什么、怎样下单？ | 加购、立即购买 |
| How It Works | 从开始到结束到底怎么用？ | 产品、指南、演示 |
| Collection / Accessories | 有哪些选择、差别是什么？ | PDP 或相关商品 |
| Support Center | 我需要的帮助在哪里？ | 分类、教程、文档、客服 |
| Article / Guide | 完整信息和下一步是什么？ | 相关内容、下载、求助 |

产品足够简单时 Overview 和 PDP 可以合并；复杂硬件或内容较多时分开表达。不是所有网站都要电商路径。

## Home

可选顺序：核心价值与双 CTA → 产品/服务入口 → 核心亮点 → 场景 → 适用人群 → 结果演示 → 媒体/真实口碑 → 深入演示 → 价值或成本解释 → 购买保障 → 订阅/最终 CTA。

每段都服务于认知和分流。相同卖点可以在不同页面复用，但首页保持摘要，PDP/详情再展开。

场景卡通常一张图、一句标题、一句解释。多个人群若需要轮播，画默认屏和下一屏，标明 `1 / 2` 与左右控件。案例、前后对比或污渍演示可做独立视频卡，不必添加重复描述。

## Product Overview

页内导航 → 产品/场景 Hero → 核心亮点 → 技术原理与收益 → 实际使用场景 → 结果与评价 → 关键疑虑 → 购买 CTA。

技术段可以用左右交替的文案与剖面、流程或特写。写清媒体需要证明什么，避免只列参数。FAQ 表达用户做选择前的疑问。

## PDP

首屏双栏：

- 左：主媒体、缩略图、数量/左右切换、图/视频切换；下方可放已确认购买保障。
- 右：名称、价格或待定值、真实评价入口、相关权益、付款说明、关键卖点、确有差异的变体、数量、加购/立即购买、配件、配送/退换及付款方式。

根据产品决定是否需要配置选择，不能单 SKU 也凭空造出型号。

首屏后可接：页内吸顶导航 → 视频 KV → 亮点 → 技术与收益 → 使用演示/UGC → 证据或媒体 → 对比 → 规格 → 操作介绍 → 包装清单 → FAQ → 评价 → 回到购买。

描述吸顶触发、锚点和返回购买区的意图。涉及价格或比较时保留计算假设与口径，不把示例计算转成保证。缺少数据时显示评价结构和待定状态，不发明评分、评论数或优惠倒计时。

## Collection / Accessories

少量商品可只用共享 Header + 标题 + 3/4 列商品卡 + Footer。商品卡通常图、名称、价格、简短用途及点击去向。

商品很多、筛选影响决策时才加入排序、筛选和空结果；不要自动给四个配件增加复杂筛选、对比表和多段 FAQ。配件销售页与配件使用帮助是两种任务。

## How It Works

全流程演示 → 3–5 步操作概览 → 必要原理 → 场景应用 → 使用前限制/准备 → FAQ → 购买/指南 CTA。步骤数由实际流程确定，不机械锁定。

目的在帮助理解流程；技术动作必须由提供的产品资料支持。未获得正式操作资料时用概念层级说明并记录资料需求。

## About / Press

About：生活场景开篇 → 品牌目的、使命/愿景/价值观 → 创始人信息或拟议寄语 → 真实用户/品牌活动 → 产品演示 → 下一步。

Press：品牌媒体介绍 → 图片、视频、Logo、新闻稿等资产入口 → 使用说明 → 媒体联系方式。区分“媒体报道证据”和“提供媒体资产”，按 brief 保留所需部分。

## Blog 列表与详情

列表：编辑型 Hero、实际内容需要的分类/搜索、示例卡片网格、分页或加载更多、页脚。卡片有主题、封面用途、摘要、日期位置；拟议文章不伪装为已发布文章。

详情：封面、标题/日期/作者（如适用）、具有真实层级的正文、小标题、图/视频、目录、相关内容、分享/返回。侧栏订阅和推荐取决于内容策略。

详情应画出正文的阅读节奏和页面底部，而不只是一个大灰框。目录必须与标题对应，列表点击应指向详情模板或已画实例。

## Support 系列

Support Center：产品帮助入口 → 配件帮助、视频教程、下载、故障排查 → Email、Chat、Ticket 等联系渠道。单产品用单产品入口，不堆产品类别选择器。

- Accessory Support：按部件/任务的指南卡，去往 Guide；提供去配件购买页的次入口。
- Tutorials：有用的分类、视频卡、书面指南入口；旁边画播放弹窗。
- Download Center：文件名称、用途、实际语言/版本/大小（有资料时）、View 和 Download。通常不需要再造文件详情页。
- Troubleshooting：问题分类、一个展开问题及其他折叠项、故障或指示灯引导、求助出口。使用客户说明书内容。
- Support Article：面包屑/返回、目录、视频、图文步骤、相关资源、反馈、联系客服。

所有类别相互可达。视频关闭回到原列表位置；View 与 Download 的动作不同；Chat/Ticket 属于外部系统时在注释中标明。

## Contact / Business / Dealer

Contact 先分流售后、媒体、企业采购、渠道、合作等实际渠道，再给必要表单和自助帮助。

B2B 采购强调数量、用途、公司与市场；Dealer 强调区域、渠道、客户、服务能力。字段由业务筛选目的决定，不复制所有项目的长表单。

表单画必填、输入/选择/长文本、错误位置、隐私提示、按钮和成功去向。提交失败保留已输入内容。画布中的表单状态不应真的向后台发送资料。

## 政策与交易系统

政策可共用模板：标题、生效日期位置、页内目录、清晰小节、求助入口。实际条款由用户提供，原型不承担法律条款生成。

交易范围按需求选择购物车、结账、完成页、账户等。购物车表达商品、配置、价格、数量、移除、总计和空状态；结账画平台实际支持的主要信息阶段并注明由平台承接。不要承诺商家当前套餐不一定支持的自定义布局。

## 状态表

| 源对象 | 触发 | 状态/目标 | 返回/异常 |
| --- | --- | --- | --- |
| 导航菜单 | 展开 | 子导航面板 | 收起；点击目标页 |
| 视频卡 | 播放 | 视频弹窗 | 关闭后保留列表位置 |
| 轮播 | 下一屏 | 第二组卡片、计数变化 | 上一屏；端点规则 |
| FAQ | 点击题目 | 展开答案 | 收起；是否单项展开 |
| 购买按钮 | 加购 | 购物车反馈或抽屉 | 缺货/未选配置 |
| 表单 | 提交 | 错误或成功 | 保留输入、重试/下一步 |

只绘制项目真正需要且会改变决策或布局的状态。
