# 来源与提炼边界

依据为过往独立站信息架构与可编辑原型项目。公开包只保留可复用的方法，不提供客户内部文档入口。整理日期：2026-09-23。

依据包括当前在线画布的总览、正式导出的矢量 PDF 内容，以及本项目对应的绘图源文件、修订记录和局部截图。当前在线画布优先于历史脚本；历史脚本中更多的旧页面不等于当前页面范围。

## 在线画布呈现的结构

- 总标题 `PROJECT WEBSITE WIREFRAMES/PROTOTYPE`，横向主页面列，黑底白字页面标签，页面由上向下完整展开。
- 独立的 Navigation + Footer 组件区；各页共享当前导航和四类页脚链接。
- 主线包含 Home、Product Overview、PDP、How It Works、About、Press、商品/配件、Blog 列表与文章、Contact、Dealer/Business、Policy、Cart/Checkout、Support Center 及支持分类/文章。
- PDP 特别长：前部为购买区，后接页内导航、大视频 KV、亮点、原理/演示、规格、FAQ、评价与转化收尾。Overview 侧重认知，PDP 侧重购买。
- Blog Article、Business Purchases、Checkout 等放在相关页面下方；Tutorial Video 有单独展开态。整板不是单一尺寸的卡片集合。
- 页面含可读英文草稿、具体媒体用途、CTA、表格、表单、文章与 FAQ；有少量保留的产品素材图。

## 可复用的设计判断

1. 把信息架构、页面叙事、文案、素材需求和交互说明放进同一套可评审原型。
2. 公共组件统一；必要状态独立表达，保持它与所属页面的空间关系。
3. 不同页面承担不同任务：配件商品页可以非常简单，产品和支持详情页可以很深入。
4. 以真实内容长度决定区块高度，重要桌面模块给足视觉空间。
5. 修订时保持用户最新编辑与相邻模块；高度变化向后传递。
6. 通过原生矢量对象保持飞书可编辑性，预览图只辅助评审。

## 不应固化的项目特例

原项目品牌及产品、英文、1200 宽、具体页面数、主导航顺序、四列页脚、Shopify/Zendesk、具体价格/评级/权益、视频或媒体名称都属于当前实例。

这些可以是新项目的起点或可选模式，但不能自动成为新客户事实、全局硬限制或强制功能。用户当前任务和资料优先。本技能不打包客户完整画布、联系方式、照片或产品商业数据。

## PixelMob 迭代依据（2026-09-22）

复盘使用本项目原型/前端任务记录、`source/design/*.drawio`、最新 `site/` 和浏览器页面。历史参考是 DJI SDR Transmission 2。B 版原型为六张视觉卡，最后页面是九张，不能把中途提议冒充最终标准。

- 用户先要求只保留完整首页，后按需补受众状态；单页不应默认附整站辅助板。
- 第二屏明确要求考虑卡片排版、文案数量/格式/一致性，方便 UI；容量与媒体比例应在线框阶段验证。
- DJI 参考反推原型：让画面承担解释，放大 Hero 和操作演示，减少嵌套卡片，精简 Tab 内重复说明。
- 工作流从“简洁”继续改为“看得出流”，不能因少字丢掉交接路径。
- 信任从品牌介绍改为“有经验的团队 + 工作中的样机”，配对应图片，分清历史与当前项目事实。
- 实现继续删除多余眉题、序号和口号，修正 Review/Cull/Create 图文关系，补已核实的选型字段；未知参数不编造。
- 九卡、100vh KV、Inter、绿色 KS CTA 和 0.7 秒动效是本次风格或业务选择；原型技能仍适用于其他风格和转化。

本次修订不代表飞书与最终 HTML 已全量同步。本地原型是历史快照；未来修改仍先读当前画布。
